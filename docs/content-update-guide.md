# 点位内容更新指南

## 1. Demo 当前更新位置

当前 Demo 为轻量单页版本，点位数据集中在：

`app/page.tsx` 顶部的 `const stops: Stop[] = [ ... ]`

每个点位由以下字段组成：

```ts
{
  id: "government",
  no: "01",
  district: "泉江镇 · 城区",
  title: "遂川县工农兵政府旧址",
  short: "县级红色政权建设的起点",
  description: "点位摘要和现场导览正文。",
  facts: [
    ["历史时间", "1928"],
    ["建议停留", "45 min"],
  ],
  tags: ["旧址展陈", "建政线索"],
  position: { top: "36%", left: "28%" },
}
```

## 2. 更新一个点位

1. 复制一个已有点位对象，保留唯一的 `id`。
2. 修改 `no`、`district`、`title`、`short` 和 `description`。
3. 在 `facts` 中填写经审定的时间、开放信息、建议停留等字段。
4. 在 `tags` 中放 1 至 3 个短标签。
5. 根据地图示意调整 `position.top` 和 `position.left`。
6. 如果是新镇区，更新 `filters` 数组。
7. 在点位图片或视频真正接入后，替换对应的 `public/media/` 文件路径。
8. 运行 `npm run lint` 和 `npm run build`。

## 3. 地图地名层

地图地名和红色点位集中在 app/page.tsx 顶部的 placeLabels 数组。行政地名使用 kind: "town"，线路节点使用 kind: "scene"，红色遗址使用 kind: "red"。

每个标签包含：

- id：唯一 ID。
- name：地图上显示的名称。
- top、left：当前 Demo 的示意位置，正式上线建议替换为 GIS 坐标。
- note：点击后显示的说明。
- stopId：如果关联点位详情，填写对应点位的 ID。

当前 Demo 按遂川县 2023 年乡镇/乡名录录入 23 个行政地名，位置为视觉示意，不代表真实经纬度。正式发布前应由项目方核对行政区划和地图底图。

## 4. 图片位

图片素材放在 `public/media/`。页面里目前有显式占位：

- 首页主视觉：`public/media/hero-surface.jpg`
- 点位图片：建议使用 `{point-id}-01.webp`、`{point-id}-02.webp`
- 视频封面：建议使用 `{point-id}-video-poster.webp`

替换素材时注意：

- 不要使用未经授权的网络图片。
- 图片文件名不要包含空格或中文。
- 每张图片准备一句准确的 `alt` 文案。
- 建筑、展陈、人物和老照片尽量记录拍摄时间与授权信息。

## 5. 视频位

路线故事视频位当前显示在故事线模块：

`public/media/route-story.mp4`

替换前确认：

- 横屏视频建议 16:9，手机视频可另备 9:16 版本。
- 准备封面图，避免视频加载前出现空白。
- 增加字幕或文字稿，保证无声环境也能理解。
- 检查视频版权、人物肖像和背景音乐授权。
- 不建议首页自动播放有声视频。

## 6. 讲解音频位

Demo 的“讲解音频位”按钮只做状态演示。正式接入时，为每个点位增加音频路径和文字稿，例如：

```ts
audio: {
  src: "/media/government-guide.mp3",
  transcript: "/media/government-guide.txt",
}
```

正式接入 `audio` 标签时，需要保留播放、暂停、进度和错误提示。

## 7. 内容审核清单

发布前由内容负责人逐项确认：

- 点位名称和行政区划准确。
- 历史时间、人物、事件和地点有可靠来源。
- 开放时间、预约方式、费用和交通信息为当前有效版本。
- 文案不把 Demo 占位内容带入正式页面。
- 图片、视频、音频拥有使用权限。
- 地图坐标与现场入口一致。
- 手机端长标题、正文、字幕和按钮不溢出。
- 修改记录中写明修改人、审核人和发布日期。

## 8. 推荐的正式内容模型

如果后续接入 CMS，建议把点位拆成：

- 基础信息：名称、别名、所属乡镇、地址、经纬度。
- 导览信息：摘要、正文、建议停留、开放信息、交通提示。
- 媒体信息：图片数组、视频、封面、音频、文字稿。
- 历史信息：时间、事件、人物、来源。
- 运营信息：发布状态、审核人、更新时间、版本号。

这样 Web 与 H5 只消费同一份内容，不需要分别维护两套页面。
